STM32F103ZET6 · 三轴/单轴 int8 CNN · SDU-QIT 刀具磨损数据 · 本页解释看板上的数字和“修正标签”是什么

1. 系统链路

传感器（目前为板内 DAC 回放）→ ADC 10.24 kHz × 1024 点（100 ms/窗）→ AC-RMS 能量门限判“空闲”→ 逐窗 RMS 归一化 → int8 3 类 CNN（初期/稳定/加速）→ 串口回传 → 本看板。

单轴固件：采集 100.0 ms + 推理 17.07 ms = 117.1 ms/窗。三轴同步固件：100.1 + 31.39 = 131.5 ms/窗。三轴 DAC 分时回放固件：300 + 31.42 = 331.4 ms/窗。

2. 三类磨损 + 空闲（为什么不是端到端 4 类）

四类信号幅度差约 27 倍，单尺度 int8 会把空闲量化到 ±1 LSB，端到端量化后准确率从 95.9% 掉到 62.2%。所以拆成“RMS 门限判空闲（几乎零成本）+ 3 类磨损 CNN（逐窗归一化）”，量化掉点 < 0.1 pt。

信号重标标签下随机口径为 92.42%（三轴）——重标把边界窗口按信号划到相邻阶段，任务更难，不是“放水”。

4. 为什么“严格时间划分 + 原始标签”这么低

原始 4 类是按“阶段文件”整段打的标签，但每个阶段文件的末段信号已经进入下一阶段（例如 steady 末段 RMS 0.045 已超过 accelerating 平均 0.040）。严格切分时测试集恰好全是每个文件的尾巴，标签写“稳定”、信号却是“加速”，模型按信号判成加速就算错。

证据：逐 10% 段测试只有最后 10% 崩（steady 14.7%、initial 55%，accelerating 100%）；严格口径错误 100% 是相邻阶段（跨档错误 0）；重标标签与原始标签一致率 76.1%。

为什么三轴回放是 300 ms：板内只有 1 个 DAC，要分 3 次放 3 个轴，每轴 100 ms；同步采集用 3 个 ADC 通道同时采，所以回到 100 ms 采集。
